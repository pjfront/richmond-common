## Projection boundaries

[projection.sql](projection.sql) uses explicit source columns and existing source relations only. [export_core.py](export_core.py) has an independent field allowlist, streams named-cursor pages, preserves exact numeric amounts, hashes every output file, checks the exact held-item identity, and refuses to overwrite an output directory. Its CLI accepts loopback source hosts only. It does not read any provider environment file or connection URL; libpq reads an existing private `PGPASSFILE` without printing it. Outputs default to ignored `exports/<UTC timestamp>/` and are not committed.

Private operator/configuration/subscriber/auth/search-log/cost-reservation tables are absent. Raw documents, extracted attachment text, embeddings, campaign assertion payloads, donor addresses and direct contact fields are absent. Names already reported in public civic/filing records are retained as reported; this does not infer identity matches. Original source URLs, source labels and available timestamps remain unchanged. Legacy civic rows do not acquire invented confidence, extraction or verification fields; their existing provenance limitations remain.

Generated summaries, recaps, biographies, vote explanations, comment summaries and influence analysis are withheld. Nullable compatibility columns satisfy basic item/meeting readers; checks prevent accidental population of those generated fields in this baseline. `conflict_flags` is an empty compatibility table with `CHECK(false)`, not an assertion that no conflicts exist. `core_projection_status` explicitly marks withheld/not-indexed/partial features and can hold source checked times and revision hashes. The basic UI must use those statuses whenever omitted coverage could otherwise look like zero activity.

Comments are omitted by default. `--comments-from YYYY-MM-DD` can opt in to recent (2026 or later), minutes-sourced public records at >=90% stored confidence; their generated summaries remain omitted. This is incomplete coverage, never “no comments.” The original full archive retains the omitted historical comments and all richer source data. Attachment binaries and attachment rows are not part of this initial core; meeting agenda links lead to the original portal/documents and their published attachments.

The exact March 2, 2010 Point Molate J-2 item remains available: item `9cf375c8-edc1-413c-8ee0-6485348fbc6f`, meeting `5f560013-daea-499a-8ecd-ca1a089c8a0c`, normalized item number `j-2`. Its two disputed indexed motions and six associated vote rows are excluded, and the schema rejects motions targeting that item. This is a hold, not a correction or evidence that no vote occurred. The original minutes and October 3 review disclosure remain the reference. The basic public display must retain that disclosure independently of any private-preview flag.

Finance is the current published `0660620:calendar-2026` index, activity **January 1–November 3, 2026**, confidence >=90%, current `source_reported`/`matched_exact` events only. A read-only source aggregate confirmed that all 1,424 copied events are `source='netfile'`; no paper/other-source event is being replaced by this electronic-only contract. It retains signed adjustments, loans, noncash activity and independent-spending roles without turning them into cash donations. All-eight-form coverage, pending counts, original links and limitations remain visible. Missing/out-of-window results do not establish absence or influence.

## Reader compatibility and the smaller-schema choice

[public-core.sql](public-core.sql) preserves existing `.from()` names and foreign-key embeds for meetings/bodies, agenda/meetings, motions/agenda, votes/motions/officials, attendance/officials, and topics/item_topics. It exposes the same named-argument/result signature for `search_site`, with read-only, bounded PostgreSQL FTS and no vector extension. The legacy `vote_explainer` result-kind name searches **source motion text** here; metadata identifies that text source. Generated explanation text remains absent. Ranking may differ from the full database, and current bounded results remain incomplete retrieval windows.

This is compatible with the **basic Search / Meetings / Money query slice**, not the whole legacy application or generic full pipeline. Council biographies, conflict reports, donor profiles, paper-processing operator tools, semantic `search_hybrid`/`find_similar_items`, accounts, email and writes need tier guards or a local/full adapter. Type casts to the full legacy generated schema are not proof that every legacy column or function exists. No fake semantic RPC is supplied.

Retirement timestamps remain writable for a future compact updater; source cancellations and withdrawn agenda rows can be retained without deleting identities or saved votes. Active-source readers must continue filtering them. Source meeting GUIDs have a unique partial index, which passed the existing snapshot. A refresh must preserve known IDs and minutes authority, use exact source identity/revision reconciliation, and disclose unmatched/pending new source records.

Importing the entire old schema with mostly empty tables would preserve more legacy function/row shapes, but also retains extension/service dependencies, private-table surface area, broad default grants, extra indexes and a pipeline that expects a document lake. Its managed baseline and runtime compatibility would still need separate measurement. The compact schema has been physically tested and makes omissions explicit; route/feature guards keep the extra surfaces closed. The full archive remains the route back to all retained data and local features.

## Safe finance refresh contract

[`src/finance_public_projection.py`](../../src/finance_public_projection.py) is a pure projector of `finance_sync.acquire_snapshot` results. It requires successful acquisition of all eight supported electronic forms, one consistent January 1/cutoff window, `snapshot_complete=True`, zero recorded model calls, original provenance and partial public coverage. It rejects duplicate identities, mixed scopes, malformed amounts/links and a cutoff older than the current snapshot. Only exact `finance_public_*` columns leave the helper; raw addresses/documents/assertion keys do not.

The compact writer must lock this scope, recheck the existing cutoff inside the same transaction, and replace the **whole bounded electronic snapshot plus all eight coverage records atomically**. Append-only events would leave superseded/amended totals visible. Failed fetch/pagination/metadata or incomplete form sets must leave the prior published snapshot intact. Public “partial” means other paper/agency/report coverage is absent; it is compatible with a completely fetched electronic acquisition. Adding another source later requires source-aware identities/replacement rules; do not reuse this whole-scope electronic overwrite unchanged. The helper tests use injected source fixtures, not fresh verified source answers or live writes.

[`src/basic_finance_acquisition.py`](../../src/basic_finance_acquisition.py) replaces the legacy unlimited transport through the existing parser's `fetch`, `filing_info` and `download` seams. Reviewed maxima are 250 transactions/page, 64 transaction pages, 10,000 transactions, 400 distinct filing metadata requests, 32 PDFs, 512 total HTTP requests, 2 MB per transaction JSON response, 256 KB per metadata response, 4 MB per PDF, 24 MB of PDF bytes and 48 MB of total response bytes. It streams bodies, rejects count/identity changes and incomplete pages, fixes Richmond's agency and reviewed 2026 date scope, disables retries/redirects/environment proxies and requires all eight electronic forms before returning. Limits may be lowered, never automatically expanded. Exceeding a limit blocks replacement and requires reviewing the source inventory rather than silently truncating it. PDFs are transient deterministic-parser input; this compact path persists no PDF bytes or private raw payloads.

The adapter checks a 300-second elapsed deadline between HTTP requests/chunks and after parsing, with 5-second connect and 20-second socket-read timeouts. This is not a hard process termination or a PDF parser memory sandbox: one in-flight read/parser call can finish after the deadline before rejection. A hosted scheduler must also have a finite job timeout and retain aggregate-only failure diagnostics. Fixture verification covers the real parser/projection contract and guard paths; fixture verification alone does not establish that today's live source inventory is below every bound.

An October 4 actual bounded finance pass subsequently completed against the isolated **local archive**: 1,551 electronic assertions, 1,424 derived events, 15 source PDF downloads and zero model calls. Archive mode retains source originals; compact mode stores only the approved public projection. This verifies the live finite transport/parser path and local archive apply; it is not a remote compact-database refresh or an activated schedule. An earlier attempt safely rejected duplicate transaction identities before finance writes. Later aggregate-only pagination inspection returned complete unique filing/transaction identities across all eight forms; that earlier failure was not reproduced or definitively diagnosed. The adapter uses the canonical `(filingId, id)` identity within each form and continues rejecting repeated full identities, inconsistent counts/pages and wrong echoed page/agency parameters.

## Reproduce locally

Use installed Python requirements and existing PostgreSQL; no system installation is required by these scripts. Supply credentials privately through `PGPASSFILE`, not command arguments. The exporter only reads an already restored local source and never connects to a target. The measurement script refuses to reuse or drop an existing database and accepts only a new `basic_core_measure_YYYYMMDD[_N]` name on loopback.

```powershell
python scripts/basic-core/export_core.py --port <local-port> --output scripts/basic-core/exports/<new-directory>
python scripts/basic-core/measure_local_core.py scripts/basic-core/exports/<new-directory> --port <local-port> --database basic_core_measure_20261004_2
python scripts/basic-core/verify_local_reads.py --port <local-port> --database basic_core_measure_20261004_2 --report scripts/basic-core/exports/<new-directory>/read-checks.json
python -m pytest tests/test_finance_public_projection.py scripts/basic-core/test_public_core.py -q
```

The bootstrap is for a **new empty database**; it intentionally fails rather than altering an existing one. It adds no provider services or paid integrations. The export manifest hashes both the projection and bootstrap, so a changed contract requires a reviewed fresh export. Before a managed import, use a separately reviewed target-specific import path; these measurement tools intentionally cannot write to a remote database.

## Free public operation and release checks

The lowest-change hosted target is a separate Supabase Free organization/project for this core plus the existing eligible Vercel Hobby frontend and a bounded GitHub updater. A Free project must not be added to GoodJobber's paid organization: a Supabase organization has one plan, and the existing oversized paid database is not this core. Current [Supabase Free quotas](https://supabase.com/pricing) include a 500 MB database and limited storage/egress; inactive Free projects can pause. This locally measured 45.5 MiB database fits the data allowance with substantial application-data headroom, but is not proof of a provisioned provider's measured size, indefinite growth or guaranteed availability.

A source refresh independent of the PC should use the new compact writer, explicit dedicated target credentials, model budget locked at $0, finite source/date/page/download bounds, a whole-database storage ceiling, and no generic enrichment DAG. New agenda entries and electronic finance can update from structured official APIs. Existing votes remain available; new unparsed minutes/votes and unsupported paper figures require disclosed pending coverage or a separately verified deterministic/local extraction path. Freshness means the last successful check and source coverage shown, not silently treating a failed fetch as zero records. The basic source-status reader/UI consumes `core_projection_status` for `agenda_refresh` and `finance`; agenda checks describe only the past-60/next-14-day window, and finance remains partial. Missing or malformed metadata must visibly say the check time/window is unavailable. Source failures leave the previous successful time and records intact, so a cutover check must confirm that older times remain visible and that no failure appears as a new successful check. After the reviewed 2026 publication horizon, agendas continue while finance is visibly `pending_review`; the writer does not open a new year implicitly. Scheduled GitHub jobs can be delayed, and public inactive schedules can be disabled; retain manual refresh and monitoring of meaningful failures.
